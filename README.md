# Covenant agent — Halyk AI Challenge

Агент читает архив документов и реестр транзакций и по каждому ковенанту
каждого заёмщика определяет статус, фактическое значение показателя и
транзакцию-улику. Результат — `submission.json` по шаблону организатора.

**На открытом наборе: 88.3% баллов по официальной шкале, 34 верных статуса
из 36.** Прогон детерминирован, полный цикл — около 110 секунд на 200
документов.

---

## Результат на конкурсе

`submission.json` в корне репозитория — файл, отправленный на приватном
наборе: 27 заёмщиков, 84 ячейки, все заполнены. Рядом лежит
`submission.json.log` — журнал прогона, по которому видно, какие факты не
нашлись и где вердикт держится на слабом основании.

На открытом наборе, где ключ доступен, агент набирает **89.7% баллов по
официальной шкале при 34 верных статусах из 36**.

## Запуск

```bash
pip install -r requirements.txt
apt-get install -y tesseract-ocr tesseract-ocr-rus

TEAM="имя-команды" EMAIL="you@example.com" ./run.sh <путь-к-датасету>
```

`run.sh` выполняет предполётную проверку окружения, прогон, печать
предупреждений агента и проверку структуры файла. Подробности установки — в
`INSTALL.md`.

Отдельные шаги:

```bash
python -m src.preflight                                        # готовность окружения
python -m src.run --dataset <путь> --out submission.json
python -m src.validate submission.json <путь>/submission_template.json
python -m src.score submission.json <путь>/ground_truth.json   # если ключ есть
```

## Архитектура

```
ingest.py     PDF → текст (кэш по md5); распознавание сканированных страниц;
              классификация типа документа; привязка к счёту заёмщика
facts.py      типизированные факты: ковенанты, структура владения,
              обеспечительное покрытие, корректировки аудитора, курсы валют
ledger.py     категоризация строк реестра, валютный пересчёт, применение
              корректировок, нормализация наименований контрагентов
formulas.py   распознавание формулы ковенанта правилами → Spec
llm.py        распознавание формулы моделью, когда правила не сработали
spec.py       Spec и детерминированный исполнитель — единственное место,
              где считается арифметика
run.py        оркестратор; гарантирует заполнение каждой ячейки шаблона
preflight.py  проверка окружения перед прогоном
validate.py   проверка структуры submission.json
score.py      локальная копия официальной шкалы оценки
selftest.py   сверка LLM-разбора формул с таблицей правил
test_llm.py   офлайн-тесты обвязки LLM (33 проверки)
```

Разделение принципиальное: **извлечение фактов допускает нечёткость, расчёт —
нет.** Все суммы в `Decimal`, округление до двух знаков — один раз, на выходе.

Ковенант описывается как данные, а не как код:

```python
Spec(numerator=[{"category": "capex"}],
     denominator=[{"category": "opex"}, {"category": "lease"}],
     direction="max", limit=Decimal("0.42"), limit_kind="ratio")
```

Формулу распознают два эшелона. Первый — таблица правил в `formulas.py`; она
не дрейфует, поэтому при совпадении ей доверяют безусловно (покрывает 36 из 36
ковенантов открытого набора). Второй — модель, которая читает текст ковенанта
и возвращает такой же `Spec` в JSON. Модель ничего не вычисляет; её ответ
проходит валидацию, и всё непрошедшее отвергается, а не чинится. Незнакомая
формула перестаёт быть дырой в покрытии и становится обычным случаем.

Вызовы модели кэшируются на диск по хешу содержимого, идут с `temperature=0` и
параллельно. Без ключа API модуль возвращает `None`, и конвейер работает на
одних правилах.

## Что оказалось нетривиальным в данных

### Реестр

Колонки категории нет — категорию несёт `description`. Наименование
контрагента для подавляющего большинства строк случайно и никак не связано с
назначением платежа: «Hartley Building Services Holdings» платит страховую
премию. Опираться на контрагента можно только там, где он действительно
значим: выручка, аренда, платежи связанным сторонам.

Из 1473 строк 800 относятся к посторонним счетам с числовым префиксом
(`TXN-9001-…`). Заёмщик определяется префиксом `txn_id`, и только им.

**Пустая сумма — это не ноль.** У части строк колонка `amount` пуста;
`Decimal("NaN")` тихо отравляет любую сумму, в которую попадает. Такие строки
помечаются и исключаются из расчёта, пока служебная записка казначейства не
сообщит фактическую сумму.

### Две редакции договора

У каждого заёмщика есть исполнительный экземпляр и редакция 2024 года с
пометкой «НЕДЕЙСТВУЮЩАЯ РЕДАКЦИЯ». Пороги в них различаются. Агент никогда не
читает недействующую редакцию — не выбирает между ними, а отбрасывает по
признаку в шапке.

### Три статуса аудиторского документа

Промежуточные рабочие ведомости с пометкой «НЕ ЯВЛЯЕТСЯ ОКОНЧАТЕЛЬНОЙ
ПОЗИЦИЕЙ АУДИТОРА» игнорируются целиком.

Примечания к отчётности могут сослаться на «отчёт о выполнении согласованных
процедур № AR-2025-0634» и не повторять вывод. Отсылка распознаётся и
пропускается, чтобы корректировка была взята из авторитетного документа ровно
один раз.

**Отклонённая реклассификация читается почти как принятая.** «Рассматривалась
на предмет переклассификации как Страховые премии; по итогам разъяснений
первоначальная классификация сохраняется» — тот же глагол, та же сумма, та же
целевая статья, противоположный смысл. Отдельные ковенанты это прямо
оговаривают. Признак отказа проверяется до того, как глаголу доверяют.

### Аудитор указывает операцию суммой, а не идентификатором

«Сумма в размере $592,296.10, выплаченная контрагенту Irtysh Advisory Bureau,
переклассифицирована как Процентные расходы» — `txn_id` здесь нет.
Сопоставление идёт по сумме, наименование используется только для разрешения
неоднозначности. Несопоставленная корректировка пишется в лог, а не
проглатывается молча.

### Индивидуальный порог связанной стороны

Порог не 20% и не берётся из МСФО — он напечатан в самом досье и различается
по заёмщикам: 20.0, 25.0, 30.0, 32.0, 34.0, 35.0, 36.0, 38.0. Доли подобраны
так, что крупнейший неконтролирующий участник почти всегда оказывается чуть
ниже порога: 18.7 против 20.0, 23.4 против 25.0, 28.6 против 30.0, 33.5 против
36.0, 36.2 против 38.0.

Признак связанной стороны в этом контуре задаёт договор, а не внешний
стандарт. Агент применяет договорное определение и логирует его источник.

### Наименования в таблице владения испорчены намеренно

Причём систематически — именно у той организации, которая порог проходит:
`Syrdarya Capital Holding, LLP`, `"Saryarka Capital Partners" LLP`,
`Ulytau Capital LLP.`, `Ertis Capital, LLP`, `Aral Capital Partners, LLP`.
Регулярное выражение, опирающееся на аккуратную организационно-правовую форму,
теряет ровно контролирующего участника и обнуляет весь тест по всем заёмщикам
сразу.

### Отсканированные страницы

Шесть страниц архива — изображения без текстового слоя. `extract_text`
возвращает по ним пустоту, `extract_tables` тоже, и документ выглядит
неполным, а не повреждённым. На них лежат несущие таблицы: структура владения
двух заёмщиков, обеспечительное покрытие дочерних организаций и перечень
разовых статей для корректировки EBITDA.

Страница считается сканом, если содержит изображение и меньше десяти символов.
Такие страницы рендерятся и распознаются, результат дописывается к тексту
документа. Тип документа определяется по регистрационному номеру досье, а не
по наличию таблицы: иначе сканированное досье ушло бы в шум.

Таблицы разбираются **по структуре, а не по словам**:

```
строка данных   заканчивается процентом      Zhetysu Capital Partners LLP 31.2%
правило         содержит процент в середине  ... владеет 25.0% и более ...
```

Один и тот же разбор работает по исходному тексту и по распознанному, в том
числе без русского языкового пакета.

### Курс валюты — в примере, а не в таблице

Ковенанты требуют пересчёта «по курсу, раскрытому аудитором». Таблицы курсов
нет: есть счёт на 72,146.75 EUR, урегулированный платежом $83,690.23. Курс —
частное этих чисел. Строка, для валюты которой курс не раскрыт, не
пересчитывается по выдуманному курсу, а фиксируется в логе с суммой.

### Номер пункта — адрес ячейки, а не тип теста

У большинства заёмщиков 6.3 — платежи связанным сторонам, но у одного это
потолок капитальных затрат; 6.1 имеет свою формулу у каждого заёмщика.
Диспетчеризация идёт по тексту ковенанта, не по номеру.

### Документы-ловушки

Статусные отчёты и процедуры комплаенса упоминают вспомогательные счета
(`ACC-7801-08`), соседние юрлица с той же основой наименования
(`Aktau Port Services AG` при `JSC`) и содержат правдоподобные суммы. Документ
привязывается к заёмщику только если содержит ровно один основной номер счёта.

## Отказоустойчивость

Конвейер не падает: сбой на одной ячейке даёт запись в лог и значение по
умолчанию, остальные ячейки считаются. Извлечение текста кэшируется по хешу
файла. Порядок обхода детерминирован — два прогона на одном входе дают
идентичный файл.

Рядом с `submission.json` пишется `submission.json.log`: по нему видно, какие
факты не нашлись, какая корректировка не сопоставилась и где вердикт держится
на слабом основании.

Отсутствие распознавания или ключа API не останавливает работу, но и не
проходит незамеченным — `preflight` сообщает об этом до прогона, а не после.

## Проверка перед отправкой

```bash
python -m src.preflight                    # окружение
python -m src.test_llm                     # 33 проверки обвязки, без сети
python -m src.selftest --dataset <путь>    # сверка LLM-разбора с правилами
```

`selftest` отвечает на вопрос, который важен на незнакомом наборе: **если бы
таблицы правил не было, восстановила бы модель те же формулы?** Он разбирает
каждый ковенант дважды и сравнивает не только структуру `Spec`, но и число,
которое эта структура даёт. Ниже 80% совпадений — выход с ненулевым кодом.

## Что добавилось на приватном наборе

Приватный набор шире открытого: 302 документа против 200, 27 заёмщиков против
12, 84 ячейки против 36. Правила те же, но появились новые формы входа.

**Идентификаторы не одного вида.** Наряду с `ACC-7801` встречается
`TELE-4471`, а идентификаторы операций бывают многосегментными
(`TXN-KC-OPX-12`). Маршрутизация документов теперь ведётся по списку счетов из
самого реестра: он авторитетен и устойчив к любому формату, а заодно отсекает
правдоподобные номера из документов-ловушек, которых в реестре нет.

**Документы на двух языках.** Договор может быть озаглавлен `EXECUTION COPY`, а
недействующая редакция — `SUPERSEDED — PRIOR-YEAR AGREEMENT`. Классификатор
распознаёт оба языка, и признак недействующей редакции проверяется первым:
прошлогодний экземпляр тоже называет себя договором.

**Нумерация пунктов не фиксирована.** У большинства заёмщиков ковенанты в
статье 6, у одного — в статье 5, у части их четыре, а не три. Извлечение
ведётся по списку пунктов из шаблона подачи: он авторитетен относительно того,
какие ячейки существуют. Границей блока служит заголовок следующей статьи —
иначе последний ковенант поглощает весь остаток договора вместе с
ограничительными обязательствами, где случайные «не менее» и «от выручки»
переворачивают направление теста.

**Досье бывает трёх видов.** Помимо таблицы владения встречаются именованные
записи («Контрагент "X" классифицирован как АФФИЛИРОВАННОЕ ЛИЦО») и прямое
утверждение «Связанные стороны среди контрагентов не выявлены». Последнее —
находка, а не пробел: при нём эвристический подбор связанных сторон
отключается, иначе агент выдумал бы их там, где досье говорит об обратном.
Запись о Ограниченной дочерней организации так же однозначна: она
устанавливает, что контрагент связанной стороной *не* является.

**Корректировки EBITDA стали массовыми.** Разовые статьи раскрываются двумя
способами: поимённо по идентификатору операции либо таблицей сумм с порогом
существенности («разовыми признаются статьи в сумме не менее $500,000.00»).
Порог — часть арифметики ковенанта, а не комментарий: статьи ниже него не
прибавляются.

**Два ковенанта могут носить одно имя при разных определениях.**
«Капиталоёмкость» у одного заёмщика — это капитальные затраты к операционным
расходам и аренде, у другого — к выручке. Распознавание идёт по формуле,
записанной в тексте, а не по заголовку.

**Двухусловные тесты.** Нарушение наступает только при одновременном
превышении двух порогов, либо при наступлении любого из двух. Исполнитель
получил вторую проверку как штатную возможность: отчётным остаётся основной
показатель, второе плечо влияет только на вердикт.

### Чего датасет не содержит

Четыре ковенанта измеряются на уровне консолидированной Группы. Ни
консолидированной отчётности, ни показателей материнской компании в архиве
нет — эти величины неисчислимы по имеющимся данным. Собственный реестр
заёмщика не является их заменой, и подстановка его в качестве ответа была бы
уверенной ошибкой, а не вынужденным пробелом. Такие ячейки помечаются в логе.

### Категоризация по существу, а не по формулировке

Описания операций в разных наборах сформулированы по-разному: «sales
settlement», «bulk cement sales» и «wholesale interconnect revenue» — всё это
выручка. Поэтому шаблоны опираются на существо операции, а порядок проверки
разделяет близкие случаи:

* передача активов дочерней организации — это капитальные затраты, но
  проверяется до общего шаблона оборудования, чтобы остаться опознаваемой;
* ремонт, восстановление и обслуживание восстанавливают существующий актив и
  относятся к операционным расходам, а не к капитальным;
* капитальные затраты — это *приобретение*: «Equipment yard lease» называет
  оборудование, ничего не покупая, поэтому шаблон опирается на глагол
  приобретения, а не на слово «оборудование».

### Досье может отвечать сразу на два вопроса

Одно и то же досье может содержать и таблицу владения, и именованные записи. Но
записи о дочерних организациях отвечают на другой вопрос — находится ли
контрагент внутри периметра обеспечения, — и не должны отменять таблицу
владения в том же документе. Аффилированность устанавливает только запись,
говорящая об аффилированности.
